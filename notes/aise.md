# 🌊 Waterfall

Let's start with the traditional approach.

```text
Requirements
      ↓
Design
      ↓
Development
      ↓
Testing
      ↓
Deployment
```

This is **Waterfall**. It works well when requirements are stable and well understood. What happens if the customer changes an important requirement near the end? **Learners discuss.** Exactly. That is one reason software teams started exploring more iterative approaches.

 
### 🔄 Iterative Development

Instead of trying to build everything in one massive cycle:

```text 
Build -> Test -> Improve -> Repeat
```

We continuously improve the product. Each iteration gives us a better version of the software. 
 

### ⚡ Agile

Now we reach Agile. Agile emphasizes:

* Small increments
* Frequent delivery
* Early feedback
* Customer collaboration
* Continuous improvement

Popular Agile approaches include:

* Scrum
* Kanban
* Extreme Programming

The important mindset is:

> **Don't wait until the end to discover that you built the wrong thing.**

Deliver. Get feedback. Learn. Improve.Repeat.
